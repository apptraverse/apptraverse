# Локальное состояние устройства и события окружения

Контракт уточнён пользователем 16 ноября 2026 года. Windows WindowCatalog —
первый потребитель; общие объекты и сравнение не зависят от Win32.

## Хранение и перенос

`ClientLocalState` — сохраняемый маркер корня локального графа. При дистилляции
создаётся обычный объект с собственной областью владения `ObjectScope.root_id`.
Его значения, исторические базы и Events используют ту же сериализацию слоёв
`ObjId/ClassId/S`, что остальные объекты. Новые локальные Events получают область
владельца через `CommitLocal`. Чисто runtime-объекты не становятся локальными
сохраняемыми объектами: HWND/HMONITOR/HFONT, подписки и результаты layout не пишутся.

`ClientLocalDomainStorage` направляет записи отмеченных графов в отдельный
`RamDomainStorage`; `OverlayDomainStorage` по-прежнему применяет обычные правила
USER/BACKING. Штатное сохранение записывает `<profile>/user.bin` для переносимых
объектов и `<profile>/local/user.bin` для LOCAL. Это один формат объектного
хранилища, а не собственный INI/JSON или checkpoint. Закрытие дочернего окна
по-прежнему сохраняет только в RAM; диск записывается при завершении приложения.
Ссылка на локальный корень остаётся в переносимом графе, его содержимое — в LOCAL.
Исторический снимок каталога удерживает эту identity как live-reference, не
встраивает старую копию локального состояния в свою историю.

При переносе модель обновляется всегда. Локальный граф можно передать как seed
на новое устройство. `SeedClientLocalStorage` принимает seed только при отсутствии
собственного графа назначения, целиком сохраняет существующий LOCAL и не смешивает
снимки двух устройств. В Windows load-only сборке `--local-seed-dir <source-local>`
подключает такой первоначальный seed. При имеющемся LOCAL источник даже не читается.
После переноса устройство самостоятельно изменяет локальные объекты.

`UiDeviceState` содержит предпочтение Auto/Light/Dark и смягчения тёмной темы,
последний снимок ОС, наблюдения окон и желаемое размещение. Предпочтения меняются
через Proxy/Event/publication, изолированы по профилям, применяются ко всем окнам
этого приложения. Существующий `%LOCALAPPDATA%/.../appearance.ini` больше не
читается и не изменяется; автоматической миграции экспериментального формата нет.

## Снимок и события

Снимок `UiDeviceEnvironment` содержит:

- системный DPI X/Y и масштаб текста в тысячных;
- текущую системную тему, семантические цвета, High Contrast;
- системный message font (имя, высота, вес, italic);
- предпочтение уменьшения анимации, клавиатурные подсказки, системный флаг
  screenreader; последний является подсказкой ОС, не проверкой наличия читателя;
- признаки поддержанных настроек: отсутствие API отличается от выключенной настройки;
- активные логические экраны: ключ, границы и рабочая область в desktop pixels,
  primary, ориентация и частота обновления. Количество выводится из списка.

Список сортируется по ключу: изменение порядка перечисления не создаёт Event.
Сравниваются значения, а не названия пришедших Windows messages.

При запуске Windows adapter считывает реальную ОС на UI thread. Model prepare
сравнивает её с загруженным LOCAL **до первой публикации и создания окон**:

- предыдущего снимка нет — `UiDeviceEnvironmentChangedEvent` с признаком
  `kEnvironmentInitialized`, `had_previous=false`;
- значения изменились — тот же Event с предыдущим/новым снимками, причиной
  `kStartup` и маской DPI/displays/resolution/work-area/text/colors/accessibility;
- всё совпало — Event и новая generation не создаются.

Во время работы тот же путь использует причину `kSystemNotification`.
`ObserveEnvironment` не меняет бизнес-состояние каталога или constraints.
`UiWindowEnvironmentChangedEvent` отдельно описывает фактический монитор, DPI
и геометрию конкретного окна по его ObjId, без сохранения HWND.
Оконный DPI читается через optional `GetDpiForWindow`, на Win7 — системный DPI.
Число DPI из одного окна никогда не считается DPI всех мониторов.

## Разрешение размещения через Events

Для каждого окна отдельно сохраняются предпочитаемый и фактически выбранный
экран. Ключ Windows — PnP monitor device-interface path, возвращаемый
`EnumDisplayDevicesW(..., EDD_GET_DEVICE_INTERFACE_NAME)`. Если виртуальный/RDP
экран не предоставляет его, используется явно обозначенный `gdi:` endpoint key.
Это локальная identity подключения, не глобальный серийный номер: замена драйвера,
порта или установки может дать другой ключ. Смена DISPLAY1/DISPLAY2 сама по себе
не отменяет привязку при наличии PnP interface path.

`ObserveEnvironment` после принятия снимка формирует
`UiWindowMonitorResolvedEvent` для изменившихся разрешений размещения:

- `kFound`: предпочтительный экран существует, он выбран;
- `kMissing`: экран исчез, выбран primary, либо первый доступный экран;
- `kUnavailable`: экранов нет, применение размещения откладывается.

Изменение рабочей области/разрешения/DPI также выпускает новую ревизию запроса
размещения. Replay применяет уже принятый выбор, не обращается к ОС и не создаёт
вложенные Events. Если экран вернулся, новое событие возвращает окно на него.
Автоматический fallback сохраняет первоначальное предпочтение. Законченное
пользовательское перемещение (`WM_EXITSIZEMOVE`) или явный model frame request
обновляет предпочтение; служебные `WM_WINDOWPOSCHANGED` сообщают только факты.

Размер и положение сохраняются в DIPs относительно рабочей области, без
глобального offset прежнего desktop. Презентер применяет опубликованный выбор,
получает реальный DPI целевого HWND, переводит DIPs в pixels и ограничивает окно
доступной рабочей областью. Переполнение содержимого остаётся задачей общего
layout engine/scrollbars. Наблюдение получившейся геометрии идёт обратно Event-ом
и не превращает применение запроса в новое пользовательское перемещение.
Наблюдения iconic/zoomed frames не перетирают нормальное размещение;
сохранение maximized-состояния остаётся ранее отложенной отдельной возможностью.

## Windows adapter и границы

Используются `WM_SETTINGCHANGE`, `WM_THEMECHANGED`, `WM_SYSCOLORCHANGE`,
`WM_DISPLAYCHANGE`, `WM_DEVICECHANGE`, `WM_POWERBROADCAST`, `WM_DPICHANGED`,
а также существующие optional WinRT text/color subscriptions. Polling нет.
Повторные одинаковые уведомления от нескольких окон подавляются сравнением
снимков и модельным no-op. Метрики и отрисовка обновляются сразу на UI thread;
для доступности текста не требуется ждать публикации. Сохранённые OS-факты —
baseline сравнения, а не команда применить старые настройки к Windows.
High Contrast сохраняет приоритет над выбранной темой.

Win7 путь использует User32/GDI/SPI; новые DPI/WinRT API загружаются динамически.
Автоматическая раскладка не делегируется системным layout solvers.
Нормальный Debug сохраняет политику fresh graph в отдельном `debug-run-*/user`;
для восстановления нужно использовать load-only и тот же профиль/поставку.
Прототип S0-only: прежние экспериментальные профили сохраняются отдельно,
не мигрируются и не читаются новой несовместимой схемой.
