# UpdateLab: локализация, S1 и обновления устройства

Независимый opt-in пример на AppTraverse и его native-объектной системе.
Обычный WindowCatalog и его S0-профили не меняются. Одно нативное окно Win32/GTK:
текст, listbox языка, список версий, пользовательская заметка, клоны и прогресс.

## Запуск

Windows, Visual Studio 2022/v143, Debug:

```powershell
./tools/build_update_lab.ps1
./tools/start_update_lab.ps1
```

Первый запуск поднимает отдельный клиент Æther, хранящий компоненты, и приложение
через launcher. Идентичность клиента хранится в его отдельном профиле.
`./tools/start_update_lab.ps1 -FileSource` явно выбирает файловый источник для
локальных тестов; обычный запуск использует UID клиента Æther.

Для проверки в окне выберите R1 и Русский, затем R2 и Deutsch. Закройте окно во
время прогресса и запустите тот же скрипт: загрузка продолжится. R3 перезапустит
приложение на E1 и покажет S1 у прежних клонов. Добавьте клон, сходите в R0 и
вернитесь в R3. Кнопка проверки сбоя скачивает E2 и возвращает рабочую E1.
Экспортированный USER импортируйте в Linux-профиль со своими локальными настройками.

Linux: `bash tools/build_update_lab_linux.sh /absolute/build/directory`.
GTK 3 и clang нужны для сборки. Для ручного запуска:

```sh
update_lab_provider --store /path/store --profile /path/component-client --endpoint-file /path/endpoint.txt
update_lab_launcher --install /path/installation --profile /path/profile --seed /path/update_lab_e0 --provider CLIENT_UID
```

Linux-скрипт сохраняет обычные Debug-бинарники, а для доставки создаёт копии без
debug-секций. `publish` принимает EXE обеих платформ в одном запуске, чтобы один
клиент компонентов обслуживал Windows и Linux. При изменении самих тестовых
сборок используйте новые каталоги STORE/профиля: опубликованные ID неизменяемы.

Для единого каталога после Linux-сборки в WSL:

```powershell
./tools/build_update_lab.ps1 -LinuxBinaries '\\wsl.localhost\Ubuntu\home\nickc\update-lab-build\update-lab-package'
```

Путь указывает на `update-lab-package` выбранного Linux build-каталога.
Без `-LinuxBinaries` Windows-скрипт публикует только Windows EXE.

## Версии

Обнаружение будущих поставок пока не реализовано: обычный старт завершённой
установки не делает запрос проверки обновлений, сохранённый catalog не
освежается. UI и fixture имеют фиксированные R0–R3/E0–E2. Поэтому появление
нового E3 на стороне дистрибуции само по себе не обновит запущенную R1.
Текущие сообщения — запрос catalog и запрос блока компонента; отдельный
`resolve-update` с текущими R/E, платформой и каналом — предложенный контракт,
а не существующая команда этого прототипа.

| Поставка | Содержимое | Исполняемая версия |
| --- | --- | --- |
| R0 | Исходные English/Русский, объект TextObject/S0 | E0 |
| R1 | Заменён перевод существующего текста | E0 |
| R2 | Добавлен Deutsch, загружаемый отдельно | E0 |
| R3 | Новый слой TextObject/S1 с badge у префаба и старых клонов | E1 |

E2 — намеренно неисправный исполняемый файл для кнопки проверки отката.
Версия поставки и выбранный язык коммитятся вместе. При возврате в версию без
Deutsch явно выбирается English. Идентичности клонов, пользовательский S0 и
пользовательское переопределение S1 сохраняются при ходе назад и вперёд.
S1 берётся штатной загрузкой слоя через `Obj::origin_id()`, без ручного копирования
полей по списку клонов. Не переопределённый S1 не закрепляется в USER.

## Состояние и перенос

| Место | Содержимое | Перенос между устройствами |
| --- | --- | --- |
| `profile/user.bin` | Штатный native USER: язык, R, заметка, клоны, base/history | Да, через один `.ats` |
| `profile/local/user.bin` | DeviceState: имя устройства, положение/размер, скорость загрузки | Нет |
| `profile/local/transfer/user.bin` | DownloadNode и его Events/base | Нет |
| `profile/local/components/` | Завершённые компоненты и незавершённые `.part` | Нет |
| `profile/local/download-identity/` | Идентичность клиента Æther устройства | Нет |
| `installation/` | Launcher journal, слоты EXE, снимок для отката | Нет |

Кнопки Export/Import переносят только USER. Импорт сохраняет существующий LOCAL
полностью, а нужные поставка, язык и исполняемый файл целевой ОС скачиваются заново.
Каждая упакованная полная версия или дельта — один самодостаточный файл `.ats`;
индекс и содержимое графа не разнесены по дереву файлов. Отдельные локальные
разделы не включаются в переносимый USER.

DownloadNode — настоящий `NodeFor<..., ClientLocalState>`. `DownloadChanged`
состояниями `queued/catalog/progress/ready/error/activated/staged/rolled-back` передаёт намерение,
список компонентов, принятые байты, готовность и ошибку. Коммиты выполняются
модельным потоком; worker только получает байты и возвращает результат через
очередь runtime. UI получает штатную сериализованную публикацию и отдельное
зеркало; ввод идёт через ModelObjectProxy.

Блок `.part` сначала записывается и flush-ится, затем сохраняется Event прогресса
и native DownloadNode. После рестарта лишний незакоммиченный хвост усекается;
запрашивается следующий блок. Завершённые компоненты остаются в кеше при смене
намерения. Идентификаторы компонентов версионированы и считаются неизменяемыми.
Контрольных сумм и подписей нет: доставка прототипа считается безошибочной.

После готовности всего набора модель коммитит язык и R одним UserChanged,
атомарно заменяет `user.bin` и делает одну публикацию нового интерфейса.
Пока набор скачивается, сохраняется прежний текст и выбранный активный язык.

## Обновление EXE

EXE скачивается тем же клиентом и тем же DownloadNode. Он распаковывается в
другой слот; работающий файл не перезаписывается. Перед пробным запуском
сохраняются USER/LOCAL и атомарный journal `staged`. Приложение завершается
кодом 42; launcher запускает кандидата с состоянием `trial`.

Подтверждение приходит после загрузки модели, применения поставки и потребления
готовой публикации интерфейсом. Только тогда launcher переключает активный слот.
Выход кандидата с ошибкой, таймаут подтверждения и прерванный trial при следующем
запуске восстанавливают предыдущие USER/LOCAL и запускают прежний EXE.
Кеш скачанного сохраняется. Кнопка неисправного обновления запускает настоящий
другой EXE E2, который завершается до подтверждения.

## Упаковщик полных образов и дельт

`update_lab_pack publish --out STORE ...` создаёт R0–R3 и три соседние дельты,
языковые компоненты и указанные EXE для Windows/Linux. Имена аргументов EXE:
`--windows-x64-e0/e1/e2`, `--linux-x64-e0/e1/e2`.

`images/Rn.full.ats` содержит весь native-граф поставки, включая объекты
`LocalizationState` всех её языков. `images/Rn-Rnext.delta.ats` содержит изменения
этого полного графа: R1 меняет существующие переводы, R2 добавляет объект Deutsch,
R3 добавляет слой S1. Рядом остаются `.native.bin` для сравнения и анализа.

Для асинхронной доставки тот же граф разделён на основной supply и независимые
языковые компоненты. Каждый языковой компонент несёт собственный полный native-граф
локализации; текст для UI получается штатной загрузкой этого объекта. Сетевые
`delta/n/n+1` обновляют основной supply, а выбранный язык запрашивается отдельно.
Искусственные 384 KiB в delivery-конверте языкового пакета делают прогресс и
прерывание заметными; в канонический граф, полные образы и бенчмарк они не входят.

Для произвольных снимков native-состояния:

```text
update_lab_pack full user.bin 0 R0.full.ats
update_lab_pack delta before.bin after.bin 0 1 R0-R1.delta.ats
update_lab_pack apply before.bin R0-R1.delta.ats 0 after.bin
update_lab_pack inspect R0-R1.delta.ats
```

Дельта содержит изменённые native `(ObjId, ClassId, S)` слои, удаления слоёв,
классов и объектов, tombstones, пустые native-карты и метаданные scope. Исходный номер R обязателен: дельта не
применяется к другой версии. Сначала собирается отдельный результат, затем он
заменяет активный RAM BACKING. Соседние переходы в примере упражняют дельту;
скачок через несколько версий и отсутствие базового образа используют полный образ.
Старая версия доступна из своего полного образа; обратные дельты не требуются.

Формат ATSTATE1: вид full/delta/blob, from/to, размер распакованного native
содержимого и один Zstandard frame без checksum. Настройка упаковщика:
level 19 для состояний/дельт, level 9 для EXE/языковых blob, windowLog 20
(до 1 MiB истории); декодирование — libzstd.
Выбор по замерам описан в [анализе компрессоров](update_lab_compression.md).

## Проверки

`update_lab_state_test` проверяет точное воспроизведение полного native-графа
дельтами, удаления/tombstones, контроль исходной версии и штатный S1/origin.
`tools/test_update_lab.py` запускает отдельные процессы, принудительно обрывает
закачку, проходит версии, проверяет EXE/rollback и, с `--linux-bin`, двусторонний
перенос Windows/Linux. Каждому прогону нужен новый `--run`; чужие профили не удаляются.

`tools/test_update_lab_cloud.py` — явный сетевой прогон через UID отдельного
клиента Æther: принудительный обрыв, докачка, EXE и откат. Файлового источника
в этом прогоне нет. Транспорт использует cloud route SDK и нумерованные части
с offset: повтор/порядок сообщений не меняет собранный блок. Контрольных сумм нет.
`--native-smoke` упражняет нативные команды Win32/GTK, proxy, Events, mirror и
фактические текст/выбор контролов; успешный процесс оставляет `native-smoke.ok`.

Фактически выполненные проверки и ограничения окружения фиксируются отдельно
в [результатах](validation/update-lab-2026-11-22.md).
